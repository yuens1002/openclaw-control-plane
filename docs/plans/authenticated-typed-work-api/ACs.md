Status: drafted for plan review. Implementation has not started, so Agent, QC,

| AC-CONFIG-001 | D2 | security | Versioned configuration | Run schema fixtures for valid and invalid config. | A generic v1 fixture parses; duplicate `(issuer, subject)` identities, duplicate principal IDs, unknown roles, invalid delegation targets, unsupported providers/algorithms, unsafe names, and out-of-range clock skew fail with stable non-secret errors. | | | |

| AC-TRUST-001 | D4 | security | Trust-field spoof resistance | Submit actor, principal, delegation, role, authorization, digest, request-ID, and timestamp fields through every command-capable payload surface. | Reserved fields are rejected or ignored according to the documented envelope and can never replace the server-derived trusted command context or server-owned metadata. | | | |
| AC-DENIAL-001 | D4 | security | Bounded denial | Deny one command and one authorized-resource query through the policy boundary and inspect persisted state. | Each denial routes through the runtime service's bounded audit operation with principal/delegation, action, resource, policy, decision, reasons, origin, and request ID; no work item, action attempt, result, artifact, or projection effect is created. | | | |
| AC-WORK-001 | D5 | backend-architect | Typed intake lifecycle | Create a registered event and a work item derived from authorized record references, then attempt malformed, unknown, retired, and unauthorized variants. | Valid intake persists typed records and ordered provenance with server-derived attribution; every invalid variant fails before a partial record or edge is stored. | | | |
| AC-APPROVAL-001 | D5 | backend-architect | Immutable approval record | Authenticate an approver, record approve/reject decisions for a server-canonicalized command revision, and read the resulting record. | The stored approval binds principal, actor/delegation, authorization decision, operation, work item, revision, and server-computed digest; callers submit no trusted approver context and cannot mutate or reuse the record for a different command. | | | |
| AC-QUERY-001 | D5 | backend-architect | Kind-complete reads | Seed event, work item, action attempt, approval, non-artifact result, artifact, audit, edges, and projection records, then use the service query boundary. | Authorized callers can retrieve every seeded kind and traverse ordered provenance without direct repository access or consumer-specific schema knowledge. | | | |
| AC-QUERY-002 | D5 | backend-architect | Bounded pagination | Exercise first/next pages, kind/type/sequence filters, malformed cursors, excessive limits, and cross-resource authorization. | Results use stable ordering and opaque cursors, enforce a documented maximum page size, reject malformed bounds consistently, and never reveal an unauthorized record's existence. | | | |
| AC-REGISTRY-001 | D5 | backend-architect | Registration lifecycle | Query active registrations and attempt commands against active, unknown, and retired versions. | The public catalog is bounded and non-secret; new commands accept only active exact versions, while unknown or retired versions fail before persistence with stable errors and historical records remain readable. | | | |
| AC-HTTP-001 | D6 | backend-architect | Versioned authenticated API | Exercise all documented `/v1/runtime` routes with missing, invalid, allowed, and denied bearer credentials. | Operational routes require bearer identity in production, apply their declared authorization action/resource, return one stable error envelope, and expose no legacy unauthenticated write path. | | | |
| AC-HTTP-002 | D6 | backend-architect | Idempotent command adapter | Retry an equal command during in-progress and terminal states, then reuse its key with changed content. | Equal retries preserve one operation reference and service result; changed canonical content returns the service conflict without a duplicate effect and retains conflict audit. | | | |
| AC-HTTP-003 | D6 | backend-architect | Approval binding | Execute an approval-required operation by immutable approval ID, then independently change target, arguments, effects, revision, executor, and referenced approval. | The server rebuilds the RFC 8785 envelope/digest from the actual call and resolves trusted approver evidence from storage; only an exact valid approval executes and every mismatch fails before effects. | | | |
| AC-HTTP-004 | D6 | backend-architect | Compatibility | Run the existing `/events`, root, health, and shell regression tests with development auth disabled/enabled as documented. | Existing valid event inserted/duplicate semantics remain available through the authenticated service boundary, health remains public, and no legacy pipeline stub bypasses production authorization. | | | |
| AC-TOOL-001 | D7 | backend-architect | Authenticated tool client | Invoke representative command, record, projection, provenance, and audit tools with a rotating async token provider and inspect requests. | Each call obtains and sends the current bearer token, uses the versioned HTTP contract, validates typed inputs/outputs, forwards no trusted-context field, and returns stable API failures without leaking the token. | | | |

## Gate 1: Plan To AC Coverage

Every deliverable D1-D11 has at least one AC row. No AC references a
deliverable outside D1-D11. This must be re-run after any plan or AC revision.

## Gate 2: Anti-Drift

Pass conditions state behavioral invariants rather than tenant names, hosted
provider values, generated IDs, secrets, or one live environment. Fixtures use
only local deterministic keys and `example.*` names. This must be re-run before
implementation and during independent verification.
