## Phase 3/4 notes

One real plan/AC-authoring gap was found and fixed during verification:
AC-PROV-001 (and plan.md's command-sequence step 1) described `railway up
--new --name <client>` as the bootstrap call; the actual implementation
uses `railway init`/`link` + a plain `railway up --detach` instead,
because `--new` gives no way to control or predict the resulting service's
name. The implementation was judged correct (internally consistent, fully
tested, matches Railway CLI docs) and the docs were corrected to match it,
rather than changing working code to match a stale plan. This is the same
"AC/plan authoring gap" failure mode this repo's own retro history has
flagged before (see `f7e3238`) — closed here by the Phase 3/4 loop working
as designed, not by a fresh incident.
